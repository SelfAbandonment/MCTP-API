# 异常处理机制

项目通过 `REST_FRAMEWORK["EXCEPTION_HANDLER"]` 注册全局异常处理器，将 DRF 异常转换为统一响应结构。

## 响应结构

```json
{
    "code": 400,
    "message": "validation error",
    "data": {
        "username": ["This field is required."]
    }
}
```

`message` 是稳定的错误类别，字段级详情放在 `data` 中。不要依赖具体的字段文案；文案可能随 Django/DRF 版本变化。

## 异常映射

| 异常类型 | HTTP 状态码 | `message` |
|----------|-------------|-----------|
| `ValidationError` | 400 | `validation error` |
| `NotAuthenticated` / `AuthenticationFailed` | 401 | `authentication required` |
| `PermissionDenied` | 403 | `permission denied` |
| `NotFound` | 404 | `resource not found` |
| 其他 DRF 异常 | 异常对应状态码 | 异常详情 |
| 未被 DRF 捕获的异常 | 500 | `internal server error` |

## 注意事项

- 生产环境必须将 `DEBUG=False`，避免向客户端暴露调试信息。
- 500 错误的详细 traceback 应通过服务端日志排查，不应写入 API 响应。
- 业务校验失败应优先使用 serializer 的 `ValidationError`，保持字段错误可定位。
